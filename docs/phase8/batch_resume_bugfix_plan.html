📌 背景（なぜ直すか）

不具合症状状態
① ネスト変数 $変数 の値の中の $別変数 が、通常生成では多段展開されるのに 再開時だけ展開されずリテラルが残る（枚数も減る） 修正対象
② ドロップダウン 履歴を開くと一瞬複数件出るが、即座に最新1件へスナップバックし2件目以降を選べない 修正対象

不具合① 再開時に json_vars を補完してネスト変数を展開

根本原因（確定）

  • batch_runner.py の resume 分岐(L84-86)は履歴の used_variables だけで merged を作り、vars/variables.json 全件(json_vars)を読まない。
  • 保存側(L189-195)は expansion_order のトップレベル変数のみ保存 → ネスト先変数が履歴に残らない。
  • 結果、expand_prompts(_MAX_NESTED_DEPTH=12)が辞書にキーを見つけられず展開停止。

修正方針 案A 採用

resume でも json_vars を読み、優先順位 inline > saved > json でマージ。 再現性のため saved を優先しつつ、欠落ネスト変数を json が補完。 既存の欠落履歴もその場で救済でき、スキーマ変更不要（後方互換）。

不採用(案B): 保存時に推移閉包を収集 → 既存履歴を救済できず、実装増、 スキーマ形状変更で承認対象に。将来要件が出るまで保留。

変更内容（resume 分岐 L84-86 を置換）

# inline > saved > json の優先順位でマージ
parsed = expander.parse_main_prompt(main_prompt)
json_vars = variables_store.load_variables(_variables_path)   # 追加
merged = expander.merge_variables(
    parsed.inline_vars,
    expander.merge_variables(saved_vars, json_vars),
)
order = saved_order

_variables_path・variables_store import は既存。追加 import 不要。 order 拡張も不要（order 外変数も出現順で内側展開される）。

テスト（L1 新規 tests/test_resume_nested_variables.py）

  • ネスト変数が json 補完で全展開（枚数も検証）
  • saved が json に勝つ（再現性）
  • inline > saved > json の3段優先
  • 旧マージでリテラル残留する RED 対比

L2 実機確認

ネスト変数入り variables.json で生成→Interrupt→履歴選択→「再開する」ON→Generate。 展開しきり・リテラル残らず・通常生成と同枚数。修正前の欠落履歴でも救済を1件確認。

意図的な挙動変更: saved に無いネスト先変数は現在の json 値で補完 （従来リテラル）。saved にある変数は saved 優先で再現性維持（HIS-08 順守）。

不具合② 履歴ドロップダウンのスナップバック

根本原因（確定）

ui_builder.py の history_dropdown.focus(...)(L71-75)が outputs=[history_dropdown] で自分自身に gr.update(choices, value) を返す。 開いた瞬間に再描画されメニューが閉じ、value が最新（先頭）へ戻る。

ドロップダウンを開く(focus)→ 自身のchoices/value更新→ 再描画でメニュー即閉じ→ 最新1件にスナップバック

修正方針 更新ボタン方式 採用（ユーザー選択）

focus 配線を削除し「🔄 履歴を更新」ボタンへ。クリックで compute_focus_update() をそのまま再利用。「開く」と「再描画」が分離され スナップバックが原理的に消え、Gradio バージョン非依存。 既存テスト test_history_dropdown_focus.py は無改変で流用。

変更内容（build_ui 内 L65-75 を置換）

# focus ハンドラ・配線を削除し以下へ
refresh_btn = gr.Button("🔄 履歴を更新", size="sm")

def on_refresh(current_value):
    fresh = _history_choices(base_dir)
    new_choices, new_value = progress.compute_focus_update(current_value, fresh)
    return gr.update(choices=new_choices, value=new_value)

refresh_btn.click(fn=on_refresh, inputs=[history_dropdown], outputs=[history_dropdown])
# change(...) 詳細連動は維持 / return [history_dropdown, resume_check] は不変

L2 実機確認

2件以上（interrupted 含む）の履歴で2件目以降をクリック → スナップバックせず選択保持・詳細更新。生成後「🔄 履歴を更新」で反映。

意図的な挙動変更: 「開いた瞬間の自動再計算」(UI-04)を廃止し、 ボタン押下時に再計算する方式へ。
