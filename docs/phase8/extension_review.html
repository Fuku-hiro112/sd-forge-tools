R-1 🔴 Variable Manager → Forge 送信テキストが旧記法（動作しない）

ユーザーメモ「修正1: 実装ビルダーが旧実装になっている」の実体。コード根拠つきで確定。

経路: Manager の sendToForge()（forge.js:223）→ POST /set_jobs → Prompt Expander の「📥 Variable Manager → メイン Prompt に投入」→ メインプロンプトに書き込み → 生成。

問題: builder.buildDefs()（builder.js:187-201）が出力する定義行が現行 expander の文法と不一致:

// builder.js が生成するテキスト（旧 v3b 記法）
char=1girl, alice !! bad anatomy   ← $ なし・!! ネガ記法
---                                  ← 「変数---」開始タグなし
$char // { a;b } // $outfit          ← { } シャッフル記法

# 現行 expander が要求する文法（expander.py）
変数---
$char = 1girl, alice                 ← _DEF_RE は行頭 $ 必須
---
  • 定義行に $ が無いため _DEF_RE（expander.py:38）にマッチせず、変数定義がすべて本文扱いになる
  • !! negative 記法は expander に存在しない（negative は variables.json の negative フィールド経由のみ）
  • { a;b } シャッフル記法は存在せず、_LEGACY_N_RE（{数字}のみ）にも掛からないため警告すら出ずリテラル残留
  • 開始タグ 変数--- が無いので --- 単独は区切りとして機能しない

→ 機能判断が必要: (a) builder を現行記法に更新して残す / (b) 「送信→投入」機能ごと廃止（Manager は variables.json 同期に専念。プロンプト構築は本文で直接 $変数 を書く現行フローで足りる）。個人的推奨は (b)。sync_variables 経由の同期が既にあり、責務も明確になる。廃止なら pending_jobs / set_jobs / peek_jobs / 投入ボタン / builder.js の大半が削れる。

R-2 🟠 CORS ミドルウェア未適用の可能性（Manager 同期の生命線）

api_endpoints.py:37-45 と prompt_expander.py:104-112 の両方が on_app_started（= サーバ起動後）に app.add_middleware(CORSMiddleware) を呼び、例外を except: pass で握り潰している。

  • Starlette は起動後の add_middleware で RuntimeError: Cannot add middleware after an application has started を投げる実装がある → その場合 CORS ヘッダは一切付かない
  • Manager は file:// で開く設計（Origin: null）のため、CORS 未適用なら sync/SSE/set_jobs 全て失敗する
  • 二重登録（両モジュール）自体も冗長。どちらか一方・確実な方法（例: FastAPI ルートで明示的にヘッダ付与、または forge の --cors-allow-origins 起動オプション案内）へ一本化すべき

→ 実機で curl -i -H "Origin: null" http://127.0.0.1:7860/vram_safe_batch/api/variables を実行し、access-control-allow-origin ヘッダの有無を確認。無ければ修正必須（Manager が現在動いているなら Starlette 版が古く通っている＝バージョン依存の時限爆弾）。

R-3〜R-5 プログラム面のバグ・設計不備

R-3 🟠 Prompt Expander の seed=-1 処理（要 L2）

prompt_expander.py:731-734 は seed=-1 のとき p.all_seeds=[-1]*n のまま forge に渡す。forge の processing はスクリプトが設定した all_seeds を尊重するため、-1 がそのままサンプラー側に流れて全画像同一 seed になる/エラーになる可能性がある（dynamic-prompts は事前に乱択してから渡す実装）。batch_runner 経由では補正される（batch_runner.py:116-121）が、通常生成では補正が無い。→ seed=-1 で 3 枚展開し、infotext の Seed が 3 枚で異なるか実機確認。

R-4 🟠 peek_jobs の破壊的 GET

api_endpoints.py:67-76。GET なのに 1 回で内部バッファを消費する。txt2img/img2img 両タブに投入ボタンがあるため、片方で押すともう片方では「受信データなし」。また投入 JS が textarea 反映に失敗しても（R-1 の textarea 不在等）バッファは既に消えており再試行不可。→ 消費は明示の DELETE/POST にするか、R-1 で機能ごと廃止なら本 API も削除。

R-5 🔴 検索置換: 非正規表現モードの置換文字列エスケープ漏れ

text_replace.js:81 の text.replace(re, replacement) は、非 regex モードでも置換文字列中の $& $` $' $1〜を特殊解釈する（JS の仕様）。Python 側 text_tools.py:133 の pattern.sub(replace, text) も同様に \1 \g を解釈する。プロンプトは $変数 を多用するため「alice → $1girl」のような全置換で壊れる。1件置換（JS:67-68 の literal 連結パス）は安全で、全置換のみのバグ。→ 非 regex 時は JS で replacement.replace(/\$/g,"$$$$")、Python で re.sub に lambda m: replace を渡す。

R-6/R-7 🟡 Stable Diffusion 標準機能・既存拡張との重複

本拡張の機能標準/既存の対応物評価
シードモード「連番」（prompt_expander） forge 標準のバッチ挙動そのもの（Batch count で seed+i） 付加価値ゼロ。価値があるのは「固定」のみ。UI を「シード固定（構図維持）」チェックボックス 1 個に簡素化できる
単一値の $変数（例: $quality = 定型タグ集） 標準 Styles 機能（保存済みスタイルの挿入・infotext 記録・UI 完備） 重複。本拡張の価値は「複数値の総当り」「negative 連動」「外部 Manager 編集」にあり、単一値用途は Styles を案内すべき（ユーザーメモ不具合1 = Styles 由来の事故もこの混同が背景）
$変数 総当りバッチ X/Y/Z plot「Prompt S/R」/ prompts_from_file / sd-dynamic-prompts combinatorial README 自認済み。差別化点は「本文直書きの書き味 + 履歴/再開」。逆に言えば履歴/再開が完成しない限り存在意義が弱い → 現在の Step2/3 実装が最重要という裏付け
VRAM Recycler（毎画像 empty_cache+gc.collect） forge 自体のメモリ管理（load/offload 設定、--always-offload-from-vram 等） empty_cache は PyTorch のキャッシュ済みブロックを OS に返すだけで次の確保が遅くなるトレードオフ。断片化対策としては有効な環境もあるが、「効いた」実測（3 連続生成の VRAM 推移ログ）が残っていない。L3 で効果を数値記録し、効果が無ければ削除も検討
batch_runner 内の自前展開 fallback（batch_runner.py:124-146） 同リポジトリの prompt_expander（AlwaysOn で常時展開） 内部二重実装。PE が AlwaysOn で常に populate する現設計では、fallback が生きるのは「PE のチェックを OFF にして Batch Resume だけ使う」場合のみ。展開エンジンを 2 系統保守するコスト大 → PE 必須化して fallback 削除を検討
Text Replace (Ctrl+F) 標準・既存拡張に対応物なし（ブラウザ Ctrl+F は textarea 内を検索できない） 重複なし・存在意義明確（R-5 の修正は必要）
