通常生成の履歴保存・中断再開プラン

対象: 通常生成（Prompt Expander 経由・Script 未選択）でも履歴を記録し中断再開できるようにする ＋ 再開再現性の不整合修正

📌 背景（なぜ直すか）

ユーザー確認の結果、「通常生成でも履歴を記録し中断再開できるべき」= 仕様バグと確定。

経路いつ動くか履歴保存
① Batch Resume
(Script)		 Script ドロップダウンで「Batch Resume」を選択して Generate 保存される
batch_runner.run_batch が history_v2 を呼ぶ
② 通常生成
(Prompt Expander / AlwaysOn)		 Script 未選択で普通に Generate（日常のメインフロー）。$変数 があれば自動展開 保存されない
prompt_expander.process は history_v2 を呼ばない

②の経路では履歴が一切残らず、中断しても「途中再開」に出てこない。これを解消するのが本計画の主目的。 履歴記録を共通化する過程で、再開時の再現性の不整合も同時に修正する。

対象外: 多段展開（不具合①）・履歴ドロップダウン snapback（不具合②）は origin/main dd4f05c で修正済み。本計画では触れない。

Step 0 前提：ブランチ取り込み

作業ブランチ claude/japanese-text-interpretation-9182qc に origin/main(dd4f05c) を取り込む（merge）。 現作業ツリーは dd4f05c 未適用のため、これをしないと修正済みコード（merge_variables_for_resume 等）と衝突する。

Step 1 履歴エントリ生成の共通化（再現性の不整合も同時修正）

history_v2.py に薄いヘルパを追加し、batch_runner と prompt_expander の両方が同じ記録ロジックを使う（ドリフト防止）。 この一箇所で 3 つの既存不整合を修正する。

不整合現状修正
B1 clip_skip generation.clip_skip を保存するのに再開時に復元しない build_generation_dict に含め、resume で復元
B2 negative positive は used_variables を保存するのに、変数由来の追加ネガは再開時に現在の variables.json から再計算（非対称） 展開後ネガティブ effective_negative をスナップショット保存し、resume はこれを優先使用
H4 extensions create_entry(extensions=...) が未使用で固定値。「使用機能を保存」要件が未充足 seed_mode・hires(enable_hr)・VRAM Recycler 有無など検出可能な機能を記録

追加するヘルパ

  • build_generation_dict(p, seed_mode, resolved_initial_seed) … width/height/cfg/steps/sampler/scheduler/initial_seed/resolved_initial_seed/seed_mode/clip_skip
  • create_entry(...) を拡張し prompt.effective_negative と extensions を保存（後方互換: 旧エントリは get でフォールバック）

Step 2 Prompt Expander に履歴記録を追加（書き込み）

PromptExpander に Script ライフサイクルフックで記録を実装。VRAM Recycler の postprocess_image と同じ流儀。

二重記録ガード

BatchResume.run の冒頭で p._batch_resume_owns_history = True を立て、 prompt_expander はこれが真なら記録しない（展開は従来通り）。

Batch Resume の内側生成では prompt_expander は展開済みの具体プロンプト（$なし）を見て早期 return するため 元々二重展開は起きないが、フラグで記録を明示的に抑止して安全側に倒す。

フック実装

フック処理
process() 展開成立(n>1)かつ非ガード時、resolved_initial_seed を解決し entry 作成（status=running, completed=0, total=n、effective_negative/used_variables/extensions 込み）。p._pe_history_id / _pe_total / _pe_resume_offset(=0) / _pe_counted(set) を stash
postprocess_image() idx = getattr(p,"iteration",0) を使い iteration 単位で completed をバンプ（_pe_counted で重複防止）。completed = resume_offset + idx + 1
postprocess() 終了時に status 確定（shared.state.interruptedなら interrupted、completed≥total なら completed）
残課題 A の本質対策: ADetailer/Hires が 1 プロンプトで複数 image を返しても、 iteration 基準でカウントするため過剰カウントしない（「生成されてないのにカウント」の根治）。

Step 3 Prompt Expander に「📂 途中再開」UI を追加（読み込み）

Script を選ばず再開できるよう、Prompt Expander の Accordion 内に再開 UI を追加。dd4f05c の更新ボタン方式を踏襲。

  • 既存 ui_helpers._history_choices / _entry_detail / _parse_dropdown_index と progress.compute_focus_update を再利用
  • 構成: history_dropdown + history_detail + resume_check + 「🔄 履歴を更新」ボタン（focus 自動更新は使わない）
  • script_args に history_dropdown, resume_check を追加 → process() で受け取る

再開時の process()

  • resume_check ON かつ選択エントリが running/interrupted のとき、エントリから main_prompt/negative/order/seed_mode/resolved_initial_seed/clip_skip を復元（B1）
  • expander.merge_variables_for_resume(inline, saved, json)（dd4f05c 追加済み）で展開
  • completed 枚をスキップ: 
    p.all_prompts = expanded[completed:]
p.all_seeds   = [progress.compute_seed(seed_mode, resolved_initial_seed, completed+1+i)
                 for i in range(total-completed)]
p.n_iter      = total - completed
p._pe_resume_offset = completed   # postprocess_image のカウント継続用
  • ネガティブは保存済み effective_negative を優先使用（B2）
中断（completed=K まで保存）→ 履歴選択 + 再開ON→ all_prompts = 残り(K以降)→ 標準ループで続き生成
標準 Forge ループは「残りプロンプトだけ生成」で自然に再開できる。 batch_runner の skip_until ループは不要。

Step 4 batch_runner のパリティ修正

  • apply_resume_settings に clip_skip 復元を追加（B1）
  • resume のネガティブを保存済み effective_negative 優先に変更（B2）。Step 1 の共通ヘルパ経由で実装
