ローカル検証手順

通常生成の履歴保存・再現性修正（現時点の変更）をローカルで確認する方法

L1 = 自動テスト（forge 不要） L2/L3 = forge 実機 対象: Batch Resume 経路の B1 / B2 / H4

⚠ 今回確認できる範囲

現時点で実装済みなのは 共通ヘルパ（L1） と Batch Resume 経路の再現性修正（clip_skip 復元 / ネガティブのスナップショット / 使用機能の記録）です。

未実装: 「通常生成（Script 未選択）で履歴を積む・再開する」UI（Step2/3）。したがって通常生成で履歴が積まれる確認はまだできません。この HTML は現在の変更分の検証手順です。

L1 自動テスト（forge 不要・最初にこれ）

リポジトリのルートで実行。純関数（履歴 dict 組立・復元・再開スライス・カウント）を検証します。

# リポジトリのルートで
cd /path/to/sd-forge-tools
python -m unittest tests.test_normal_gen_history -v

# 期待
Ran 19 tests ... OK

履歴エントリの構造を目視したい場合（forge 不要のスナップショット確認）:

python - <<'PY'
import sys, json; sys.path.insert(0, "scripts")
from types import SimpleNamespace
from vram_safe_batch_modules import history_v2 as h
p = SimpleNamespace(width=512, height=768, cfg_scale=7, steps=20,
    sampler_name="Euler a", scheduler="Karras", seed=123, clip_skip=2,
    enable_hr=True, hr_scale=2.0, hr_upscaler="Latent")
e = h.create_entry("$char, masterpiece", "text", ["char"], {"char": ["alice"]},
    h.build_generation_dict(p, "sequential", 123),
    extensions={"source": "batch_resume", "seed_mode": "sequential",
                **h.collect_extension_params(p)},
    effective_negative="text, bad anatomy")
print(json.dumps(e, ensure_ascii=False, indent=2))
PY

generation.clip_skip / prompt.effective_negative / extensions.hires が入っていれば OK。

forge へ反映（L2/L3 の前に）

更新したファイルを forge にコピーし、古い .pyc を消してから再起動します。

FORGE=/path/to/stable-diffusion-webui-forge
cp -r scripts/* $FORGE/scripts/
# 古いキャッシュを削除（重要）
find $FORGE/scripts/vram_safe_batch_modules -name '*.pyc' -delete
# forge を再起動
履歴ファイルは $FORGE/batch_history.json、変数は $FORGE/vars/variables.json です。確認は cat $FORGE/batch_history.json（jq があれば | jq '.entries[0]'）。

L2/L3 forge 実機テスト

共通の前提: メインプロンプトに $char, masterpiece（$char は 2 値以上定義＝複数枚生成）。Script = Batch Resume を選択。

#手順期待（合格条件）
A
B1		 clip_skip 復元
  1. Clip skip = 2 に設定して Generate → 1 枚目の後に Interrupt
  2. Clip skip を 1 に変更
  3. 「📂 途中再開」で当該履歴を選択 → 「再開する」ON → Generate
 再開画像の infotext が Clip skip: 2（1 ではなく履歴の 2 が復元）
B
B2		 ネガティブのスナップショット（前提: $char に negative 値を設定済み）
  1. ネガティブ text で Generate → Interrupt
  2. vars/variables.json（or Variable Manager）で $char の negative を別の語に変更
  3. 同じ履歴から再開
 再開画像の Negative prompt が変更前（履歴保存時）の値。編集後の語は入らない
C
H4		 使用機能の記録
  1. Hires.fix ON（scale 2）＋ ADetailer ON（ad_prompt に detailed face）
  2. Generate（1 枚生成されれば Interrupt で可）
  3. $FORGE/batch_history.json の先頭エントリを開く
 extensions.source == "batch_resume" / extensions.hires.enabled == true / extensions.adetailer.ad_prompt == "detailed face" / prompt.effective_negative あり
D
L3		 CUDA / 連続生成
  1. A〜C の生成中、起動ログに Device: cuda
  2. 同じバッチを 3 回連続 → VRAM が単調増加しない（nvidia-smi）
  3. 中断→再開で歯抜け（欠番）が出ない
 CPU fallback なし・VRAM 蓄積なし・生成画像が破綻していない
Test A/B は「再開時に履歴の設定が正しく戻るか」の確認です。再開再現性（B1/B2）は今回の主眼なので重点的にお願いします。

L1 が緑 & A〜D が期待通りなら、現在の変更（Step1/4）は確認完了。次は Step2/3（通常生成での履歴記録・再開 UI）に進みます。
